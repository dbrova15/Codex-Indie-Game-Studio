# Godot: адресна робота

Прочитай цільові сцени/ресурси/скрипти та потрібний канон за [картою проєкту](docs/project-context.md). Виконуй вже обраний за чинними AGENTS маршрут; додаткові story/readiness/review/done документи не потрібні. Використовуй уже прочитаний незмінний контекст; після паузи або зміни відновлюй потрібне з файлів. Відсутній канон не замінюй припущеннями навчальної гри.

Статичні вузли, layout, Focus/Theme й сталі сигнали зберігай у `.tscn`/`.tres`. Не перебивай authored overrides у `_ready()`; tuning — typed export, якщо built-in Inspector-властивості немає. Shared Resource змінює всіх споживачів: для незалежної правки потрібен окремий ресурс. `%Name` обмежений owner; зберігай імена, шляхи, references та existing connections.

Перевіряй зовнішні типи/посилання до зміни стану; відхилена операція не повинна частково змінювати дані. Nullable cast може не вдатися, а вузол — бути звільненим. За наявності окремих правил/сеансу тримай їх незалежними від UI; сцена координує, дані не стають hardcoded правилами. AutoLoad, save, rollback або autoplay без продуктової потреби не додаються.

Повідомляй про зміну за фактичним ефектом у стані, на який підписані читачі: успішне повернення чи ненульовий аргумент самі цього не доводять. Перевір no-op, відмову та пакетну команду: без часткового commit і зайвих notifications; callback бачить узгоджений стан, повторна mutation не обходить guard. Оголошені події завантаження/скидання та діагностика мають власний контракт — не підміняй його загальним правилом і не вводь поріг заради тесту.

Node readiness, owner і parent мають різні ролі; після deferred scene change не припускай готовності нового current_scene в тому самому кадрі. Перевіряй Error ресурсних/сценових операцій. Standalone тест має працювати з чистим `.godot`; явний preload потрібного скрипта доречний, якщо class_name ще не зареєстрований редактором.

За [QA-контрактом](docs/qa.md) перевір спостережуваний результат і суттєві невдалі входи/межі наявними засобами. Додавай тести для справді непокритої поведінки. До завершення оглянь змінені контракти, transitions/error paths і збереження ручних значень; виправляй конкретні дефекти без нового workflow. Headless, реальний ввід, visual та Inspector мають окремі статуси. Без еталона comparison не виконаний; заява runner не заміняє перевірку логів/exit.

Заповни новий UI типовими й найбільшими заявленими даними та покажи справжню відмову. У цільовому viewport перевір важливі дії, повний error/status, довгі тексти й ріст контенту. Дозволений scroll перевір на досяжність; не виправляй обрізання приховуванням даних або непогодженим збільшенням вікна. Native geometry допомагає знайти вихід за межі; input і фактичний вигляд підтверджуй окремо.
