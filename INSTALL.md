# Встановлення в окремий проєкт

## Підготовка

Потрібні локальний проєкт, Codex Desktop або VS Code з установленим розширенням Codex. Для цього Skill не потрібні додатковий Godot addon, MCP чи нове розширення редактора. Для майбутніх Godot перевірок використовуйте engine та тести самої гри.

Не встановлюйте одночасно однойменний native plugin та цю project Skill редакцію. Перевірте також ancestor/user Skills. Якщо джерело наявного запису невідоме, спочатку з’ясуйте його; не вимикайте та не замінюйте чужі файли.

## Копіювання

1. Завантажте репозиторій через GitHub **Code → Download ZIP** і розпакуйте.
2. У корені вибраного проєкту створіть `.agents/skills/`, якщо її немає.
3. Лише якщо цільової директорії ще немає, скопіюйте туди розпаковану папку репозиторію й назвіть її `codex-indie-game-studio`.
4. Перевірте точний результат:

```text
<ваш-проєкт>/
  .agents/skills/codex-indie-game-studio/
    SKILL.md
    agents/openai.yaml
    docs/
    licenses/
    metadata/
```

GitHub додає до назви ZIP-папки суфікс гілки; при копіюванні потрібне ім’я `codex-indie-game-studio`. Не копіюйте `.git/`, якщо брали локальний Git checkout. Не додавайте ці файли в глобальний профіль. Не створюйте AGENTS/source-map/active для встановлення.

## Codex Desktop: discovery без моделі

1. Відкрийте корінь вибраного проєкту.
2. Відкрийте список Skills або селектор Skill у композері; назви елементів залежать від версії клієнта.
3. Знайдіть один **Codex Indie Game Studio** / `codex-indie-game-studio`.
4. Якщо доступні подробиці, звірте шлях з `.agents/skills/codex-indie-game-studio/SKILL.md` саме цього проєкту.
5. Для discovery достатньо списку або вибору запису. Не надсилайте повідомлення.

## VS Code: discovery без моделі

1. Через **File → Open Folder** відкрийте той самий локальний корінь.
2. Відкрийте панель розширення Codex.
3. У порожньому композері введіть `$codex-indie` і перегляньте підказки. Не натискайте Enter і не надсилайте запит.
4. Знайдіть один запис і, якщо UI показує джерело, звірте project path. Після перевірки видаліть набраний текст.

Відкриття SKILL.md у редакторі доводить наявність файлу, а не discovery. Якщо Skill не з’явився, перевірте правильний root і конфлікти; за потреби самостійно перезапустіть клієнт після збереження роботи. Remote/WSL/multi-root не перевірені цією редакцією.

## Робота, оновлення та від’єднання

Запити з [EXAMPLES](EXAMPLES.md) надсилають модельну роботу; discovery їх не потребує. Skill не змінює дозволів автора чи sandbox policy.

Перед оновленням збережіть before-image та звірте поточні bytes із checksum своєї редакції. Manual changes або unknown version — конфлікт до запису. Не накладайте ZIP поверх гри цілком.

Від’єднання стосується лише точної owned папки Skill за окремим рішенням власника. Гра, канон та AGENTS не видаляються. Після цього повторно перевірте discovery; відсутність запису не доводить очищення hidden context.
